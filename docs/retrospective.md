## Общий вывод

Доминирующий паттерн ошибок — **агент решал проблему окружения изменением
кода вместо диагностики и вопроса пользователю**: пять сборок ушло на
адаптацию под Playwright, хотя ответ «на musl-агенте Playwright не встаёт —
берём Selenium» был доступен после одного probe-билда. Второй повторяющийся
тип — **предположения о доступности ресурсов** (scope credentials, состав
pip-индекса, locale стенда) вместо проверки реальным запуском. Вывод для
процесса: наличие файла ≠ работоспособность; статическая валидация
(Jenkinsfile через linter) не заменяет контролируемый прогон на реальном
агенте.
