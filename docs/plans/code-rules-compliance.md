# План приведения кода к правилам проекта

Дата: 12 ноября 2026 года. Основание: аудит текущего кода по `AGENTS.md`.
Статус: фазы 1–5 выполнены. Итог аудита — `docs/code-rules-compliance-report.md`.

Готовые [промпты для агентов](code-rules-agents/README.md) соответствуют
пяти фазам ниже и выполняются последовательно.

## Исходное состояние

- 21 тест: 7 UI и 14 unit; все 14 unit-тестов проходят.
- В 20 тестах есть команды вне `with allure.step(...)`.
- Тестовые данные встроены в сценарии; helpers ещё не перенесены
  в подготовленные пакеты.
- В `browser.py` подавляется ошибка установки размера окна.
- Разметка Page Object и unit-тестов, каталог компонентов требуют доработки.
- UI-прогон, порядок выполнения на стенде и возможность удаления пользователей
  в рамках аудита не проверялись.

## Порядок выполнения

Фазы выполняются последовательно. В каждой фазе обновляются затронутые
потребители, записи в `knowledge/components/` и примеры импорта. Обновление
каталога не откладывается до завершения всего рефакторинга.
Существующие незакоммиченные изменения сохраняются.

## Фаза 3. Allure и проверки результата

Статус: выполнено. Команды всех 34 тестов обёрнуты в `with allure.step(...)`,

и фактическим результатом без повторных вызовов методов страниц.

- Обернуть все команды в телах 21 теста в `with allure.step(...)`,

- Добавить unit-тестам `epic`, `feature`, `story`, `severity`, `title`;
  проверить полноту существующей UI-разметки.
- Добавить `@allure.step` публичным методам Page Object, включая методы

Готово, когда нет команд тестов вне явных шагов, разметка полна, unit-тесты

## Фаза 4. Обработка ошибок и освобождение ресурсов

Статус: выполнено. Подавление ошибки `set_window_size` убрано: при сбое
обязательной настройки драйвер закрывается, исходная ошибка передаётся
вызывающему коду, а сбой `quit()` добавляется через `add_note`. Ошибки
сбора артефактов диагностируются `warnings.warn` и не подменяют падение
теста. Отправка Telegram оборачивает ошибки транспорта в `TelegramSendError`
с замаскированным токеном; CLI возвращает 0 без секретов и при сбое отправки.
Добавлены unit-проверки сценариев сбоев (`tests/unit/test_browser.py`,
`tests/unit/test_reporting.py`) — всего 27 unit-тестов.

- Удалить `except Exception: pass` при установке размера окна.
  Ошибка обязательной настройки должна завершать подготовку с диагностикой.
- Обеспечить закрытие уже созданного драйвера при ошибке его настройки:
  в этом случае управление ещё не дошло до `yield` фикстуры.
- Добавить unit-проверку этого сценария: ошибка передаётся вызывающему коду,
  драйвер закрывается, тест не продолжает работу.
- Проверить остальные обработчики исключений. Ошибки получения артефактов
  должны диагностироваться и сохранять исходную причину падения теста.
- Сохранить явно установленное правило уведомлений: отсутствие секретов
  и сбой отправки Telegram не ломают сборку; секреты не выводятся в сообщения.
- Не добавлять повторы и паузы для сокрытия ошибок.

Готово, когда сбой настройки браузера воспроизводимо обнаруживается,
ресурсы освобождаются, а существующие и новые unit-проверки проходят.
