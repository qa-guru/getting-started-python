# Агент 4 — ошибки и освобождение ресурсов

Работай в репозитории `/Users/zenalark/PycharmProjects/Test-java/getting-started-python`.
Прочитай актуальный `AGENTS.md`, `docs/plans/code-rules-compliance.md`
и относящиеся к задаче разделы `knowledge/components/`.

Это задача на реализацию указанной фазы. Проверь фактическое состояние кода:
предыдущие агенты могли изменить пути и количество тестов. Сохраняй существующие
незакоммиченные изменения. Не ослабляй правила проекта и проверки тестов.
При переносе компонента обновляй всех потребителей, документацию и запись
каталога в том же изменении. Не выводи секреты и не отправляй Telegram-сообщения.
Не создавай коммиты, не публикуй изменения и не запускай CI без отдельного запроса.

Предусловие: фазы 1–3 завершены и доступны в рабочем дереве.
Фабрику браузера ищи по её актуальному пути после переноса.

Задача — выполнить фазу 4 плана:

1. Удали подавление ошибки установки размера окна через
   `except Exception: pass`. Сбой обязательной настройки должен завершать
   подготовку с понятной причиной.
2. При ошибке настройки закрой уже созданный драйвер: фикстура ещё
   не получила его и не сможет выполнить собственный teardown.
   Если закрытие тоже завершится ошибкой, сохрани исходную причину
   сбоя настройки и диагностируй вторичную ошибку.
3. Добавь содержательные unit-проверки: ошибка настройки передаётся
   вызывающему коду, `quit()` вызывается, неподготовленный драйвер
   не возвращается. Проверь сохранение исходной причины при сбое `quit()`.
   Новые тесты сразу оформи по всем правилам Allure и тестовых данных.
4. Проверь остальные обработчики исключений в затронутой инфраструктуре.
   Ошибки сохранения артефактов должны диагностироваться и не подменять
   исходное падение теста.
5. Сохрани специальное правило Telegram: при отсутствии секретов или
   сбое отправки CLI возвращает 0. Проверяй отправку только через подменённый
   транспорт; реальные сообщения не отправляй. Не выводи токены в диагностику.
6. Не добавляй ретраи или `sleep` для достижения успешного прогона.
   Обнови каталог при изменении контракта или аргументов компонентов.

Проверки:
- Запусти весь набор unit-тестов, включая новые сценарии ошибок.
- Выполни collection всех тестов и `git diff --check`.
- Проверь, что teardown нормального сценария продолжает работать.

Критерии готовности: ошибки настройки видимы, ресурсы освобождаются,
первичная ошибка сохраняется, все unit-тесты проходят, Telegram сохраняет
контракт завершения и не отправляет реальные сообщения при проверках.

Заверши работу отчётом: изменённые файлы, результат по каждому критерию,
команды и результаты проверок, ограничения и оставшиеся задачи для следующего
агента. Обнови статус своей фазы в `docs/plans/code-rules-compliance.md`;
не отмечай невыполненные или заблокированные проверки как успешные.
