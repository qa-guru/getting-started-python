# Агент 3 — Allure и диагностика проверок

Работай в репозитории `/Users/zenalark/PycharmProjects/Test-java/getting-started-python`.
Прочитай актуальный `AGENTS.md`, `docs/plans/code-rules-compliance.md`
и относящиеся к задаче разделы `knowledge/components/`.

Это задача на реализацию указанной фазы. Проверь фактическое состояние кода:
предыдущие агенты могли изменить пути и количество тестов. Сохраняй существующие
незакоммиченные изменения. Не ослабляй правила проекта и проверки тестов.
При переносе компонента обновляй всех потребителей, документацию и запись
каталога в том же изменении. Не выводи секреты и не отправляй Telegram-сообщения.
Не создавай коммиты, не публикуй изменения и не запускай CI без отдельного запроса.

Предусловие: фазы 1 и 2 завершены и доступны в рабочем дереве.

Задача — выполнить фазу 3 плана:

1. Оберни все команды тел UI- и unit-тестов в явные `with allure.step(...)`.
   Покрой подготовку, действия и проверки; связанные команды объединяй
   в смысловые шаги с названиями на русском языке.
   Декоратор вызываемого Page Object не заменяет шаг в тесте.
2. Добавь unit-тестам `epic`, `feature`, `story`, `severity`, `title`.
   Общие метаданные допустимо задать на классе или модуле средствами Allure;
   у каждого теста должны быть эффективные метаданные всех пяти типов.
   Проверь существующую разметку UI-тестов.
3. Добавь `@allure.step` публичным методам Page Object, включая `BasePage`,
   кроме конструктора. У `login` и `login_with_enter` замени внутренний
   блок шага декоратором, сохранив его смысл и избегая дублирования.
4. Проверь понятность ошибок assertions. Добавь ожидаемый и фактический
   результат там, где вывода pytest недостаточно. Не вызывай повторно
   метод страницы только ради формирования сообщения об ошибке.
5. Сохрани названия тестов, сценарии, проверки и все существующие cases.
   Тексты шагов оставь рядом со сценариями; тестовые данные используй
   из констант, подготовленных предыдущим агентом.
6. Обнови каталог, если меняются примеры использования публичных компонентов.

Проверки:
- Запусти unit-тесты с `--alluredir` в отдельной временной директории.
- Выполни collection всех тестов и `git diff --check`.
- Статически проверь отсутствие команд тестов вне явных шагов.
- Проверь JSON результатов unit-тестов: шаги и пять типов метаданных.
  Наличие декоратора в исходнике само по себе не доказывает полноту отчёта.

Критерии готовности: все тесты оформлены по правилам, исходные cases
сохранены, unit-тесты проходят, разметка подтверждена в Allure-результатах.
UI-поведение на стенде будет проверяться в итоговой фазе.

Заверши работу отчётом: изменённые файлы, результат по каждому критерию,
команды и результаты проверок, ограничения и оставшиеся задачи для следующего
агента. Обнови статус своей фазы в `docs/plans/code-rules-compliance.md`;
не отмечай невыполненные или заблокированные проверки как успешные.
