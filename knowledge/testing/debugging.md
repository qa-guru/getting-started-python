# Диагностика падений

Сначала сохрани исходную команду, выбранный стенд без секретов, версии,
traceback и материалы конкретного запуска. Не очищай `artifacts/` и Allure
перед разбором; файлы скриншотов с одинаковым именем могут перезаписываться.

1. Определи фазу: проверка окружения, collection, fixture setup, UI-действие,
   assertion, teardown или отчётность. При CI-only сбое сначала прочитай лог CI.
2. Проследи ошибку через тест → Page Object → `ElementWaits`, browser factory
   либо helper данных. Перед новым helper проверь [каталог](../components/README.md).
3. Сопоставь ожидаемое и фактическое состояние. Различай дефект теста,
   продукта, окружения и данных. Не называй единичный сбой доказанным flaky.
4. Для воспроизведения используй минимальный scope из [run-tests.md](run-tests.md).
   Воспроизведение регистрации оставляет новых пользователей на стенде.
5. Исправляй подтверждённую причину в пределах задачи. Не ослабляй проверки,
   не добавляй sleep, подавление ошибок или повторы для зелёного прогона.
6. Перезапусти исходный scope; после изменения общего компонента проверь
   его потребителей, обнови соответствующую запись каталога компонентов.

`MissingTestDataError` означает отсутствие `EXISTING_USERNAME`/`EXISTING_PASSWORD`.
Ошибка remote без URL относится к Settings, а не к локатору.
Сбой Selenium Manager/сети/браузера не является дефектом UI-сценария.
Скриншот и HTML ожидаются только при падении `call` с доступным driver;
смотри предупреждения сбора артефактов и фактические файлы.

Отчёт: подтверждённая причина с доказательствами либо оставшаяся гипотеза,
изменение, команда и результат повторной проверки. Если выполнение невозможно,
укажи конкретный недостающий доступ/инструмент/данные и непроверенную часть.
