# Добавление UI-сценария

Прочитай [AGENTS.md](../../../AGENTS.md),
[карту проекта](../../../knowledge/architecture/overview.md), ближайший тест
в нужной области и используемый Page Object.
Перед новым общим кодом проверь [каталог](../../../knowledge/components/README.md).

Тест описывает сценарий через Page Object, созданный с `(driver, settings)`;
прямые Selenium-вызовы и локаторы остаются в страницах. Используй `ElementWaits`,
`existing_user`/`new_user`, константы `test_data/consts/` и helpers
`test_data/utils/`. Сохрани явные русские `with allure.step(...)` в тесте,
декораторы страниц и Allure-разметку из AGENTS. Проверяй результат сценария;
число проверок и форма цепочки вызовов определяются сценарием.

При изменении общего компонента обнови его тематическую запись каталога
и проверь потребителей. Если появилась новая область тестов, обнови `GROUPS`
в `tools/harness.py`; новые методы существующих областей обнаружатся автоматически.

Проверь сбор и релевантные unit-тесты по
[инструкции запуска](../../../knowledge/testing/run-tests.md), затем новый
UI-сценарий, когда доступ к стенду и его операции разрешены в текущей задаче.
Регистрация оставляет пользователей; не добавляй неподтверждённый teardown.
Сообщи покрытый сценарий, изменения и реально выполненные проверки,
отдельно укажи невыполненный UI-прогон, если доступа нет.
