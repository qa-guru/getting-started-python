# Разбор падающего теста

Прочитай [AGENTS.md](../../../AGENTS.md),
[диагностику](../../../knowledge/testing/debugging.md) и
[инструкцию запуска](../../../knowledge/testing/run-tests.md).
Сохрани исходные материалы падения и проверь текущий Git diff перед правкой.
Для сбоя только в Actions сначала прочитай лог нужного CI run через доступный
коннектор либо `tools/gh.sh view-log N` по
[контракту CI](../../../knowledge/integrations/ci-github.md).

Найди фазу сбоя и проследи вызовы из теста в Page Object, ожидания, настройки
или фикстуры. Различай дефект теста, продукта, окружения и данных; не меняй
ожидаемое поведение продукта только ради совпадения с фактическим результатом.
При новом helper сначала проверь [каталог](../../../knowledge/components/README.md).

Воспроизведи минимальный разрешённый scope. Исправь подтверждённую причину
в пределах задачи, сохрани проверки и явные ожидания. После изменения общего
компонента обнови каталог и проверь потребителей. Повтори исходный scope;
нестабильность подтверждай серией изолированных прогонов только при разрешении
на их операции и стоимость. Не добавляй автоматические retry для скрытия ошибки.

Сообщи причину с доказательствами, исправление, команду/версии/exit code,
passed/failed/errors/skipped и артефакты. Если воспроизведение недоступно,
обозначь оставшуюся гипотезу и непроверенную часть, не объявляй дефект исправленным.
