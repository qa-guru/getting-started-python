# Project Rules

UI-автотесты для niffler.qa.guru: Python 3.13 + pytest + Selenium,
Page Object, Allure.

## Запуск
- `pytest` — все тесты (chrome, headless по умолчанию)
- `pytest --browser=firefox`, `HEADLESS=false pytest`
- `BASE_URL=... AUTH_URL=... pytest` — переопределить стенд
- `pytest --alluredir=allure-results` → `allure generate allure-results -o allure-report --clean`

## Конвенции
- Тесты лежат в `tests/<область>/test_*.py`; Page Object в `pages/`,
  базовый класс `pages/base_page.py`
- Page Object получает `(driver, settings)` явно; страницы не читают
  env сами — только `Settings` из session-фикстуры
- В тестах нет прямых вызовов `driver` — только через page objects
- Креды тестовых пользователей — `test_data/` + фикстуры
  `existing_user`/`new_user` (EXISTING_USERNAME/EXISTING_PASSWORD в env)
- В `test_data/consts/` выносятся только фиксированные данные для тестов,
  функций и классов: входные значения, ожидаемые результаты, наборы данных
  для параметризации. Правило действует для тестов, фикстур и Page Object,
  включая данные уровня модуля, класса и внутри функций и методов.
  Локаторы, названия Allure-шагов и технические параметры под это правило
  не подпадают. Константы данных именуются в `UPPER_SNAKE_CASE`
  и группируются по назначению в модули внутри `test_data/consts/`.
  Секреты по-прежнему хранятся только в окружении, а не в константах.
- В `test_data/utils/` размещаются только вспомогательные функции работы
  с тестовыми данными: генерация, загрузка и преобразование данных.
  Тесты, фикстуры и Page Object импортируют их оттуда.
- Инфраструктурные helpers размещаются по назначению:
  `infrastructure/browser/` — создание и настройка браузера;
  `infrastructure/waits/` — общие механизмы ожиданий;
  `infrastructure/reporting/` — отчётность и вложения.
  Локаторы и действия конкретных страниц остаются в Page Object.
- На методах page objects — `@allure.step`.
- Каждая команда в теле теста должна находиться внутри `with allure.step(...)`:
  подготовка данных, создание и открытие страниц, действия и проверки.
  Несколько логически связанных команд можно объединять в один шаг;
  отдельный шаг на каждую строку не требуется. Название шага описывает
  действие или ожидаемый результат на русском языке. Декоратор
  `@allure.step` на методе page object не заменяет явный шаг в тесте.
- Разметка тестов: `@allure.epic/.feature/.story/.severity/.title`
- Скриншот + page source на падении пишет conftest-хук в `artifacts/`
- Секреты — только env / GitHub Secrets / Jenkins Credentials,
  никогда в коде

## Надёжность тестов и проверка изменений

- **Независимость тестов.** Каждый тест запускается отдельно и не зависит
  от порядка выполнения или данных, созданных другим тестом.
- **Ожидания вместо пауз.** Используй явные ожидания Selenium;
  `time.sleep()` в тестах и Page Object запрещён.
- **Границы Page Object.** Локаторы и взаимодействия с интерфейсом находятся
  в Page Object. Тест описывает сценарий и проверяет результат.
- **Изоляция тестовых данных.** Изменяемые данные создаются отдельно для
  каждого теста. Созданные сущности удаляются через teardown фикстур,
  если стенд позволяет это сделать.
- **Ошибки нельзя скрывать.** Не подавляй исключения и не добавляй
  автоматические повторы ради успешного прогона. У проверок должны быть
  понятные сообщения об ожидаемом и фактическом результате.
- **Проверка изменений.** После изменения общего компонента проверяй
  его потребителей. Перед завершением работы запускай подходящие проверки
  и указывай, что выполнено, а что осталось непроверенным.

## Индекс переиспользуемого кода

- Оглавление каталога переиспользуемого кода — `knowledge/components/README.md`.
  Записи разделены по темам: `utils.md`, `fixtures.md`, `models.md`, `consts.md`,
  `infrastructure.md`
  в той же директории. Читай и обновляй соответствующий раздел; в оглавлении
  храни только ссылки и краткое описание тем. При разрастании раздела дели
  его по предметным областям и обновляй оглавление, не дублируя записи.
- После добавления или изменения вспомогательной функции, фикстуры,
  набора констант или другого общего компонента обязательно обновляй
  каталог в том же изменении: имя, актуальный путь импорта, назначение
  и краткий пример использования. При переносе или удалении компонента
  обновляй или удаляй его запись.
- **Актуальность каталога.** Изменение публичной функции, её аргументов
  или пути импорта сопровождается обновлением документации и примеров
  использования в том же изменении.
- Перед написанием нового вспомогательного кода проверь каталог и найди
  существующие реализации в проекте. Переиспользуй подходящий компонент
  или расширь его вместо создания дубликата.

## CI
- GitHub Actions: `.github/workflows/tests.yml` — паттерн
  "тесты с continue-on-error → отчёт и Telegram с if: always() →
  exit 1 в конце". Не нарушай этот порядок.
- Jenkins: `Jenkinsfile` — Allure-плагин + Telegram через credentials
- Уведомления: `notify_telegram.py` — всегда exit 0, без секретов skip
